# 校友身份文字标记实施计划

状态：源码实现完成，验证结果以 PR 检查为准。范围为源码、测试与 Git 交付；本次不连接网站服务器、不上传部署、不修改线上设置或账号。

## 已确认的产品规则

- 账号属于配置的校友用户组时显示“校友”。目录是否公开不影响身份，待审核申请不视为已注册校友。
- 有 `@账号` 时显示为“名称 @账号 校友 · 时间”；没有该行则沿用现有用户名位置，不添加新的账号行。
- 使用现有灰色小字与间距变量，不加胶囊、边框、图标，不替换官方、创始人等现有身份。
- 纯头像列表保持原样，点开现有用户卡片或资料后显示；只含任意文字的贡献者署名不猜测身份。
- 手机、桌面和明暗模式共用组件，长名称允许按原布局换行。

## 实施步骤

1. 从 GitHub 已合并基线建立 `codex/alumni-identity-label`。主题目标为 `codex/severe-reporting`，校友插件目标为 `main`；保留当前目录其他未提交文件。
2. 在 ISBF-Alumni 提供仅含身份布尔值的批量读取，限制单次用户数量、按真实用户 ID 判断、复用原生权限及限流。避免逐用户查询和每请求加载整个校友组，不公开申请、证明、邮箱或资料字段。无需新数据库表或 Core 修改。
3. 在 ISBF-UI 建立共享身份服务和文字组件，合并同一轮渲染请求，对失败、过期响应、退出及账号切换采取保守处理。使用确定的原生 outlet 与现有主题组件接入：首页及共享帖子列表、帖子及回复、个人资料、用户卡片、通知、校友目录、当前账号区、搜索用户，以及有真实用户对象的用户列表和聊天。没有合适扩展点的场景明确记录，不以全站 DOM 扫描或改写用户名替代。
4. 增加与风险相称的批量查询、成员变更、普通用户、账号隔离和请求状态测试；检查真实组件中的标记顺序、头像列表保持原样及不重复显示。
5. 运行相关主题检查、插件测试（环境可用时）、Prettier、ESLint、Stylelint 和差异检查。可用的原生 CI 用于服务端与真实模板验证；本地缺少完整 Discourse 时明确注明。当前截图只作为设计基线，不将临时标签截图称为实现后的回归。
6. 完成 Git 提交与可用的 GitHub PR/CI，交付已完成范围、检查结果与未验证项。不得发布、SSH 连接、使用部署密码或改动生产资源。

## 验收要点

- 真实组成员显示标记，非成员、待审核及缺失身份数据不显示。
- 身份标签与目录可见开关分离，移出组后重新读取即消失；不暴露其他个人字段。
- 同页多个用户通过有界批量查询读取；重复用户合并，失败不被缓存为非校友，旧账号响应不污染新状态。
- @账号 后的小字位置正确；既有角色、头像尺寸、操作按钮与布局不改变；无头像覆盖。
- 不修改 Core、测试依赖快照或线上环境；保留同伴修改。

## 已实现范围与扩展机制

- 自有共享帖子卡片（首页、官方、组队、市场等使用同一组件）、帖子及回复账号行、通知演员、校友目录及当前／关联账号文字区已接入共享标签。
- 原生资料、卡片及 DUserInfo 用户行使用 user-post-names、user-card-after-username、after-user-name；搜索使用 full-page-search-below-results 与 search-menu-results-type-top。
- 原生出口仅管理新增标签，通过 Glimmer in-element 渲染到该出口局部的现有 username 节点。没有搬动原生节点、进行全页扫描或使用 MutationObserver；按模型、姓名偏好、结果集合及长度变化重新定位，销毁时由 Glimmer 清理。
- 身份读取仅针对正整数真实用户 ID；已挂载用户共享请求，单批最多100个，未挂载数据释放。导航和恢复前台重新读取，无轮询；失败不当作非成员长期缓存，账号切换使旧请求失效。

## 明确未覆盖

- 此 Core 的原生聊天消息作者栏没有逐消息插槽，现有 decorateChatMessage 仅作用于正文。本次不修改该 Core 组件，也不通过观察整个聊天 DOM 插入标记，因此聊天作者暂不显示。
- 纯头像、正文内提及、Webhook 名称、未关联账号的课程／资料贡献者署名不添加标记。纯头像点开后的现有用户卡片／资料已覆盖。
- 原生后台内未使用 DUserInfo 的表格、其他插件自有纯文字名单不会被自动改写。它们需要各自稳定的用户对象和扩展点，不能声称所有站内字符串均已覆盖。
