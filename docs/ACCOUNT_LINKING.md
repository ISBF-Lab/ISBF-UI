# 关联账号入口

2026-10-10 核对运行主题和插件后，已将服务器现有账号菜单及其调用、样式和翻译补回本地仓库。账号关联接口由独立的 ISBF-Account-Switch 插件提供。

## 入口与原故障

- 桌面入口：`isbf-v2-side-nav.gjs` 调用 `ISBFV2AccountMenu`。
- 手机入口：`isbf-v2-shell.gjs` 在当前用户自己的资料页调用同一组件，传入 `@mobile={{true}}`。
- “关联账号”按钮：`isbf-v2-account-menu.gjs` 的 `toggleLinkForm` 打开用户名表单；`createLink` 向 `/isbf/account-switch/links` 提交申请。
- 管理员审批页：`/admin/plugins/isbf-account-switch/links`。批准后，新设备先验证目标账号密码及已启用的第二因素，再通过原生 Discourse 会话切换。

在隔离应用加载原运行组件后，Chrome 实际复现了故障：按钮获得焦点后被表单替换，触发 `focusout`，且 `relatedTarget` 为 `null`。原处理将其视为焦点离开菜单，在 Glimmer 渲染期间调用 `closeMenu` 并清空表单；开发模式同时抛出更新已被当前渲染读取的 `isOpen` 状态的断言。此时尚未发送关联申请，已有后端代码没有机会执行。

修复保留按钮，并通过 `aria-expanded` 表示表单状态。失焦处理仅在存在明确的外部焦点目标时关闭菜单；点击外部、Tab 移出和 Escape 仍可关闭。

## 权限与退出

入口、账号列表及关联表单仅在当前用户 `admin` 为真且 `isbf_account_switch_enabled` 启用时显示。普通成员和仅有版主权限的账号打开普通账号菜单时，不请求账号关联接口。

插件的 `AccountsController` 使用 Core 的 `ensure_admin` 独立保护列表、申请、验证、切换和撤销。设备撤销接口保留登录用户访问，供清理原有授权。退出登录调用原生会话接口，由插件会话扩展撤销设备授权，避免普通账号退出依赖管理员接口。

关联不会提升目标账号权限。切换到普通账号后，入口隐藏，不能再通过此功能切回；双向快速切换需要双方原本都是管理员。
