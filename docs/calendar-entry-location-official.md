# 日历表单、地点与来源分类

## 已确认界面

- 桌面原有导航、月历、右侧当日安排栏及宽度保持原状；不让卡片占用日期网格。
- 共享原生 DModal/Form 编辑器；页头取消、标题、保存，表单分为名称与可选地点、全天及日期时间、备注三组。没有重复的底部保存栏。
- 地点255字符；未填不显示卡片地点行。输入与错误保留，保存中不可重复提交或关闭。
- 当日安排日期标题保留；卡片只显示全天或起止时间，跨日可用简短月日区分，不显示重复完整日期或“北京时间”。
- 官方卡片沿用蓝色左边框；个人卡片仅左边框为橙色，原日期圆点及图例个人色不变。
- 官方卡片移除“来自官方消息”，查看原消息／备注／删除紧凑左对齐同排，窄屏换行；个人仍为编辑／删除。触控操作至少44px。

## 数据与权限

- 全部／个人行程／官方活动。分类依据 source_item_id，历史已保存活动及报名截止也归官方，失去来源访问权限不改变其来源类别。
- 仅查询当前用户已保存的 entries，停止调用原生社区活动查询；不删除原生记录或话题。
- 官方项仅可编辑私人备注，删除只删除当前用户记录并保留确认。地点更新沿用官方快照、版本冲突及接受／忽略机制，更新弹窗显示新旧地点。
- 新地点列和 ICS LOCATION 由日历插件兼容发布；旧 null 地点只有在官方来源可见且仍为已确认版本时只读兼容，不回填受限来源。
- 既有日期窗口、按月导航、前后台与跨日刷新、通知链接定位、订阅密钥、UID不变。筛选不改变网格行数。

## 源码对齐

生产已经使用独立 isbf-calendar-entry-editor，但该组件尚未纳入发布分支。本次将生效的提取结构一同纳入Git，再修改分组表单，避免恢复旧版自绘遮罩与焦点逻辑。

## 验证边界

运行全部主题 source checks、地点与来源分类 VM 回归、Prettier、Discourse ESLint、Stylelint及GitHub CI。检查390、430、600、601、768、1024、1440px的日期范围和源码布局约束。

用户最新要求补做基本动态检测：发布后用独立 Edge 会话检查桌面、手机尺寸及明暗模式的表单、来源分类和卡片布局，不在正式账号新增或删除行程。尚未完成的浏览器检查与 iPhone 真机检查如实记录；静态检查不代表浏览器或键盘实测。
